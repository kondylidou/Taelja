# Taelja

Taelja translates refutations produced by resolution and superposition
provers into direct, structured proofs. The input is a proof in TSTP format
generated by E, Twee, or Vampire.

A translated proof consists of the axioms, a sequence of lemmas, and the
goal. Each lemma and each goal is established either by a chain of
equalities or by a `have ... and ... hence ...` block, in which every `hence`
corresponds to one hyperresolution step. Every step cites the axiom or lemma
that justifies it. A derived clause that the input proof uses more than once
is introduced as a lemma. For a conjecture of the form `H1 & ... & Hn => G`,
the hypotheses are listed with the axioms and `G` is the goal.

Taelja supports the Horn fragment, which is determined on the problem as
stated. Every axiom and the conjecture must be a Horn clause.

## Example

The problem `test/input/thesis_example_both_lemmas.p` has five axioms and the
conjecture `p(a)`.

```
fof(ax1, axiom, ! [X] : f(X) = X).
fof(ax2, axiom, ! [X] : g(X) = f(X)).
fof(ax3, axiom, ! [X] : (g(X) = X => q(X))).
fof(ax4, axiom, s(a)).
fof(ax5, axiom, ! [X] : ((s(X) & q(X)) => p(X))).
fof(goal, conjecture, p(a)).
```

Vampire refutes the negated conjecture, and Taelja turns the refutation into
a direct proof.

```
vampire --proof tptp --avatar off test/input/thesis_example_both_lemmas.p > proof.tstp
cabal run taelja -- proof.tstp
```

```
Axiom 1: g(X) = f(X)
Axiom 2: f(X) = X
Axiom 3: g(X) = X => q(X)
Axiom 4: s(a)
Axiom 5: s(X) /\ q(X) => p(X)

Lemma 6: g(X) = X
Proof:
  g(X)
= { by axiom 1 }
  f(X)
= { by axiom 2 }
  X

Lemma 7: q(a)
Proof:
  have g(a) = a
    by lemma 6
  hence q(a)
    by axiom 3

Goal 1: p(a)
Proof:
  have s(a)
    by axiom 4
   and q(a)
    by lemma 7
  hence p(a)
    by axiom 5
```

## Building

Building requires Cabal 3 and GHC 9.6 to 9.12.

```
cabal build
```

After `cabal install`, the binary `taelja` can replace `cabal run taelja --`
in the commands of this README.

## Producing an input proof

Taelja reads the TSTP proof that a prover prints and calls no prover
itself. It has been tested with Vampire 5.0.1, E 3.5.1, and
Twee 2.7. The directory `bin/` contains builds of these three provers for
macOS on Apple silicon.

**Vampire** (<https://github.com/vprover/vampire>). AVATAR, Vampire's
clause splitting, produces inferences that Taelja does not support, so it
is switched off.

```
vampire --proof tptp --avatar off problem.p > proof.tstp
```

**E** (`master` of <https://github.com/eprover/eprover>). With
`--proof-object=3`, E prints the clause after each simplification step,
which Taelja reads.

```
eprover --auto-schedule --proof-object=3 --tstp-format problem.p > proof.tstp
```

**Twee** (`horn` branch of <https://codeberg.org/nick8325/twee>, built with
`cabal build`). Twee proves a Horn problem through an encoding in equational
logic, and `--multi` selects the encoding with tuples. With `--formal-proof`,
Twee decodes its proof into a refutation of the original problem by
resolution and rewriting, which Taelja reads.

```
twee --tstp --formal-proof --multi problem.p > proof.tstp
```

## Usage

```
cabal run taelja -- [options] proof.tstp
```

| Option | Description |
|--------|-------------|
| (none) | Print the structured proof. |
| `--tptp` | Print the proof as a TPTP derivation. |
| `--lean` | Print the proof as a Lean 4 file. |
| `--namespace=NAME` | Set the namespace of the Lean file (default: `TaeljaProof`). |
| `--lean-out=FILE` | Additionally write the Lean file to `FILE`. |
| `--debug` | Additionally print the proof tree and the matching traces. |

The command `cabal run taelja -- --horn-problem problem.p` reports whether a
problem belongs to the supported fragment.

## Verification with Lean

```
cabal run taelja -- --lean proof.tstp > proof.lean
cd lean && lake env lean ../proof.lean
```

Each axiom is rendered as a Lean axiom, and each lemma and goal as a theorem.
Every step is an explicit term constructed from the statement it cites. No
proof search is involved, so Lean accepts the file only if every step is the
inference stated in the proof.

## Testing

```
cabal test
cd lean && lake build
```

The test suite translates the proofs in `test/baseline_*/` and compares the
text, Lean and TPTP output with the reference files in `test/expected_*/`,
`lean/TaeljaVerify/` and `test/expected_tptp/`. The second command checks the
Lean reference files.
