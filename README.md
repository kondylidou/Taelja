# Taelja

Taelja converts resolution/superposition refutation proofs in TSTP format into
structured, human-readable proofs, and can emit them as Lean 4 theorems for
independent verification.

It reads the TSTP output of Vampire, E, or Twee and produces direct proofs in
two forms: `have … and … hence … by axiom N` blocks (one block per
hyperresolution step) and equality chains
(`t1 = { by axiom 1 } t2 = { by lemma 3 R->L } t3`). Every step cites a
concrete axiom or lemma. Derived clauses that the input proof uses more than
once are introduced as named lemmas with their own proofs.

## Example

Input (`resolution_example_horn_general.tstp`, Vampire output):

```
fof(f1, axiom,   t(b)).
fof(f2, axiom,   ! [X] : (t(X) => q(X))).
fof(f3, axiom,   s(a)).
fof(f4, axiom,   ! [X] : (s(X) => p(X))).
fof(f5, axiom,   ! [X,Y] : (p(X) & q(Y) => r(X,Y))).
fof(f6, conjecture, r(a,b)).
...
```

Output:

```
Axiom 1: t(b)
Axiom 2: t(X) => q(X)
Axiom 3: s(a)
Axiom 4: s(X) => p(X)
Axiom 5: p(X) /\ q(Y) => r(X,Y)

Lemma 6: q(b)
Proof:
  have t(b)
    by axiom 1
  hence q(b)
    by axiom 2

Goal 1: r(a,b)
Proof:
  have s(a)
    by axiom 3
  hence p(a)
    by axiom 4
   and q(b)
    by lemma 6
  hence r(a,b)
    by axiom 5
```

## Requirements

- GHC 9.6 and Cabal 3.
- Twee (`bin/twee`, bundled; a macOS arm64 binary) — used internally to
  justify equational steps and lemma candidates.
- E prover (`eprover` on the PATH, or set `TAELJA_EPROVER`) — used internally
  to re-prove lemma candidates from their ancestry.
- Vampire is only needed to *produce* input proofs, not to translate them.

## Usage

```
cabal run taelja -- <proof-file.tstp>
cabal run taelja -- --debug <proof-file.tstp>
```

`--debug` additionally prints the parsed units, the refutation proof tree,
per-nucleus matching traces, and timing.

Environment variables (all optional):

| Variable | Default | Meaning |
|----------|---------|---------|
| `TAELJA_TWEE_TIMEOUT` | 15 s | Budget for goal-level Twee calls (the equality chain for a goal) |
| `TAELJA_TWEE_INTERNAL_TIMEOUT` | 5 s | Budget for speculative internal Twee calls; never exceeds the goal budget |
| `TAELJA_E_TIMEOUT` | 5 s | Soft CPU budget per E lemma sub-proof (plus a 5 s wall-clock kill) |
| `TAELJA_EPROVER` | `eprover` | Path to the E binary |
| `TAELJA_STRICT` | unset | `1` forces the strict (paper) translation stage only |

## Testing

```
cabal test
```

The golden suite translates stored prover outputs for all three provers
(`test/baseline_{vampire,e,twee}/`) and compares against
`test/expected_{vampire,e,twee}/`, plus handcrafted cases. The goldens are
authoritative: they are only regenerated deliberately, and every behaviour
change or bug fix comes with its own golden. Each golden also has a Lean
module under `lean/TaeljaVerify/{Vampire,E,Twee}/`, generated by the emitter
and verified with `lake env lean`; the aggregate import list is
`lean/TaeljaVerify.lean`. On a successful translation stderr stays clean
(warnings on the success path are treated as failures by the evaluation).

CI (`.github/workflows/ci.yml`) builds and runs the golden suite on macOS
arm64 using the bundled Twee binary and Homebrew's E prover.

## Lean verification

`scripts/taelja2lean.py` renders a Taelja proof as a self-contained Lean 4
file: an uninterpreted sort, the axioms as Lean axioms, and one theorem per
lemma and goal whose proof mirrors the structured proof (explicitly
instantiated rule applications, occurrence-precise rewrites). A proof hole
becomes a reference to an undefined identifier, so an unproved step can never
verify silently.

## Evaluation

`scripts/eval.py <vampire> <tptp-dir> --eprover … --twee …` runs the three
provers over the TPTP problems classified HNE/HEQ/UEQ, feeds every proof to
Taelja, and writes `eval_out/results.csv`. Afterwards
`scripts/regen_lean_eval.py` emits Lean modules for all translated proofs and
`scripts/check_lean_eval.py` verifies each module individually.
`scripts/check_chains.py` independently checks every equality-chain step
against its cited rule.

## Algorithm

The translation follows the accompanying paper. In outline:

- **Proof tree** (`ProofTree.hs`): the flat TSTP refutation is expanded into
  a tree with bit-string positions; for each binary inference the premise
  providing the positive (or rewriting) atom is placed left of the one
  consuming it.
- **Two stages** (`Translate.hs`): a heuristic stage computes each nucleus's
  substitution θ from its conclusion in the input proof; if it leaves a goal
  unproved, a strict stage recomputes θ top-down as in the paper. The result
  proving more goals wins.
- **Matching**: each body atom of a nucleus is matched against candidate
  electrons. The one-sided match accepts only ground bindings; everything
  else goes through a two-sided match of variable-disjoint atoms (the
  electron renamed apart with a fresh suffix, substitutions composed).
- **Fallbacks**: unmatched atoms are retried via the electron's recorded
  rewriting chain, then via budgeted Twee calls; lemma candidates (derived
  clauses cited at least twice) are re-proved from their ancestry with Twee
  or E and translated recursively.
- **Goals**: the negated conjecture's atoms are proved like body atoms; goal
  variables are existential and goals are emitted at their proved instance.

## Module structure

| Module | Role |
|--------|------|
| `Types.hs` | Core data types: `Term`, `Literal`, `Clause`, `UnitEntry`, `ProofBlock`, `StructuredProof` |
| `Helpers.hs` | Substitution, matching, rewriting, literal utilities |
| `ProofTree.hs` | Proof-tree construction and position labelling |
| `Translate.hs` | The main translation algorithm (both stages) |
| `LemmaBuilder.hs` | Lemma candidates: sub-DAG translation and Twee/E re-proving |
| `TweeInterface.hs` | Twee invocations, encodings, chain parsing, budgets |
| `TptpConvert.hs` | TSTP declarations to internal clauses |
| `Emitter.hs` | Render a `StructuredProof` to the output format |
| `Debug.hs` | Debug dumps: TSTP units, proof tree, classification |

## Known limitations

- E's definitional predicates (`epredN` introduced by clausification) are not
  unfolded; the affected SYO problems fail Lean verification.
- Multi-body Horn axioms whose extra variables occur only in the body cannot
  be given to Twee's ifeq encoding soundly and are excluded from it.
- Twee itself crashes while printing the proof of CAT001-1 (upstream bug).
